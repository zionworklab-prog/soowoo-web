# 수우 술 메뉴 아카이브

이자카야 '수우'의 사케 / 소츄 / 전통주 메뉴를 손님이 방문 전에 미리 둘러볼 수 있는 안내 사이트입니다.
**온라인 주문 기능은 없습니다.** Notion DB와 연동해 유지보수합니다.

## 개발 서버 실행

```bash
npm install
npm run dev
```

[http://localhost:3000](http://localhost:3000) 에서 확인할 수 있습니다.

`NOTION_TOKEN` / `NOTION_DATABASE_ID` 가 없으면 자동으로 `lib/mock-drinks.ts`의 목 데이터를 사용합니다.

## Notion 연동 설정 (실제 메뉴 데이터 연결하기)

1. https://www.notion.so/my-integrations 에서 새 Integration을 만들고 토큰(Internal Integration Secret)을 복사합니다.
2. 술 메뉴가 있는 Notion 데이터베이스 페이지 우측 상단 `...` 메뉴 → `연결(Connections)` → 방금 만든 integration을 추가해 DB를 공유합니다.
3. 프로젝트 루트에 `.env.local` 파일을 만들고 `.env.local.example`을 참고해 값을 채웁니다.
   - `NOTION_DATABASE_ID`는 DB 페이지 URL의 32자리 문자열입니다.
4. 아래 명령으로 실제 DB의 컬럼명을 확인합니다.

   ```bash
   npm run notion:schema
   ```

5. 출력된 컬럼명이 `lib/notion.ts`의 `FIELD_CANDIDATES`와 다르면, 해당 배열에 실제 컬럼명을 추가/수정합니다.
6. `npm run dev`로 다시 실행하면 실제 Notion 데이터가 반영됩니다. 이후 Notion에서 항목을 수정하면 최대 1시간(`revalidate: 3600`) 내 사이트에 자동 반영됩니다.

## 카테고리 매핑 규칙

- Notion "종류" 값에 "고구마" 또는 "말차"가 포함되면(예: 고구마소츄, 말차소츄) **고구마 소츄** 카테고리로 합쳐집니다. 목록에서는 고구마소츄 항목이 먼저, 말차소츄 항목이 뒤에 정렬됩니다.
- "보리"가 포함되면 **보리 소츄**, "사케"가 포함되면 **사케** 카테고리로 분류됩니다.
- 그 외 값(전통주, 잔음료, 리큐어 등)은 자동으로 제외됩니다.

## 메뉴 화면 구조

- `/menu`는 사케/고구마 소츄/보리 소츄 필터와 정렬(기본순/가격순/추천순)을 지원하는 큰 썸네일 그리드(2~3열, 1:1 비율)로 술을 보여줍니다.
- 항목을 클릭하면 페이지 이동 없이 같은 화면에 팝업(모달)으로 상세 정보(도수, 산도, 지역, 주도, 정미보합, 테이스팅노트, 페어링, 손님 후기 등)가 뜹니다. 온라인 주문 사이트처럼 보이지 않도록 의도적으로 페이지 전환 없이 팝업으로만 구현했습니다.
- 산도·주도 값이 없는 항목은 빈 칸 대신 "비공개"로 표시됩니다.

## 손님 후기 설정 (선택 기능)

후기는 Postgres 데이터베이스에 저장됩니다. `DATABASE_URL`이 없으면 후기 목록은 비어있게 표시되고, 새 후기 등록 시 안내 메시지만 뜹니다 (사이트 자체는 정상 동작). 테이블은 코드에서 첫 요청 시 자동으로 만들어지므로, 별도로 SQL을 직접 실행할 필요는 없습니다.

1. [Vercel 대시보드](https://vercel.com/dashboard)에서 이 프로젝트 → **Storage** 탭 → **Create Database** → **Postgres**(Neon 기반) 선택 후 프로젝트에 연결합니다.
2. 연결하면 `DATABASE_URL`이 프로젝트 환경 변수에 자동으로 채워집니다 (직접 값을 타이핑할 필요 없음).
3. 로컬 개발 환경에도 같은 값을 받아오려면: `npx vercel env pull .env.local`
4. 후기 삭제는 작성자 자신만 가능합니다 — 등록 시 브라우저(localStorage)에 삭제용 토큰을 저장해두고, 그 토큰이 있는 후기에만 삭제 버튼이 보이는 방식입니다. 로그인 없는 사이트 특성상 다른 기기/브라우저에서는 삭제할 수 없습니다.
